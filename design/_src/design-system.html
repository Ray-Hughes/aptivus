The Aptivus system

A dark-first interface language for a tool people open when they are nervous. Calm surfaces, one confident accent, and every piece of state legible at a glance.

Principles

Five rules that decide the arguments. When two options look equally good, the one that satisfies more of these wins.

  • The code is the subject. Chrome recedes. The editor, the trace and the problem text get the contrast budget; navigation, toolbars and metadata sit one step back in --text-2 or --text-3.
  • One accent, spent carefully. The cyan→violet gradient marks the primary action and the brand. If three things on screen glow, none of them do.
  • State has a colour and a shape. Pass/fail, changed/unchanged, locked/unlocked never rely on hue alone — there is always an icon, a border, or a label alongside.
  • Density where the work is, air where the story is. The solve screen runs at 13px and 8px gutters. Marketing and profile run at 16px with 24–96px rhythm.
  • Nothing decorative moves. Motion confirms a change of state — a step advancing, a panel opening. It never loops for atmosphere.

Brand

A hexagon drawn in the brand gradient with a >_ prompt inside. The hexagon reads as a chip; the prompt reads as a terminal. Both are true.

Lockups
Gradient
■ #00E5FF 0% ■ #7C4DFF 100% 135deg
  • The gradient angle is always 135deg, top-left cyan to bottom-right violet. Never re-angled per component.
  • Text on the gradient is ink (--text-on-brand, #04070E) in both themes, never white — white on #00E5FF is 1.7:1.
  • Buttons use --brand-grad-cta, the same sweep with the violet stop lifted to #9E7BFF. Ink on the true #7C4DFF is 4.2:1 — close, and still a fail. The lift is 0.3 of a step and nobody can see it; the contrast table below can.
  • Use it for: the mark, the primary button, level/XP fills, and one hero word. Nothing else.

Typography

Inter for interface, JetBrains Mono for anything a machine produced. Two families, no exceptions — a third font is how a product starts to look assembled rather than designed.

Scale
Mono specimen
def find_pair(premiums, target):
    seen = {}                       # value -> index we saw it at
    for i, p in enumerate(premiums):
        need = target - p
        if need in seen:
            return [seen[need], i]
        seen[p] = i                 # insert AFTER the check
    return []
  • Tracking tightens as size grows. −0.022em on headings, −0.035em at display sizes, 0 at body, +0.07em on uppercase micro-labels.
  • Weight 400/500/550/600/650. No 700 outside the mono specimen — Inter at 700 on a dark ground blooms.
  • Numbers are tabular wherever they change in place: timers, step counters, gem balances, stat tiles.
  • Measure caps at 68ch for prose and 78ch for problem statements.

Elevation

On a near-black ground, shadow alone is invisible. Aptivus separates layers with surface value first, a 1px border second, and shadow only for things that genuinely float.

  • --surface-in goes darker than the card it sits in. Inputs, code wells and terminals are recessed, not raised.
  • Cards carry inset 0 1px 0 var(--hairline) — a one-pixel top highlight that gives an edge without a shadow.

Buttons

One primary per view. Everything below it is quieter by design, so the eye always knows where the commit action is.

Variants × states — every cell is live, tab through them
RestHoverFocusDisabled Primary Secondary Outline Ghost Accent Danger
Sizes, icons, toggles, loading
  • Primary = commit. Submit, Start free, Upgrade. Never Cancel, never a tab.
  • Destructive actions are outline-danger at rest and only fill on hover, so a mis-click is never one pixel away from red.
  • Keyboard shortcut hints live inside the button at 85% size and 62% opacity.
  • A loading button keeps its width and swaps its label for a spinner — the layout never jumps.

Forms

Recessed fields on raised cards. Focus is a border colour change plus a 3px quiet halo — never a bare browser outline, never nothing.

  • Labels sit above fields, always visible. No placeholder-as-label — it disappears exactly when the user needs it.
  • Errors use aria-invalid + aria-describedby and say what to do, not what went wrong.

Motion

Three durations, two curves. Anything longer than 280ms is a page transition, and Aptivus does not have those.

--dur-1 90msPress feedback, hover tint, chip highlight. Below the threshold where you notice it.
--dur-2 160msDefault. Colour, border and shadow transitions on every control.
--dur-3 280msSomething arriving or leaving: toast, panel, bar fill, ring sweep.
--easecubic-bezier(.4,0,.2,1) — state changes in place.
--ease-outcubic-bezier(.16,1,.3,1) — things entering. Fast start, soft landing.
prefers-reduced-motion collapses every duration to 0.01ms and cancels the solve confetti. It is in the core stylesheet, not per component, so nothing can forget it.

Accessibility

Non-negotiable, and cheaper to hold than to retrofit.

  • One focus rule for the whole product. :focus-visible → 2px --ring at 2px offset. It is never removed; components that need a different look change --ring, not the rule.
  • Body text meets 4.5:1, large text 3:1 on its own surface, verified per theme in the contrast table above.
  • Colour is never the only signal. Passing tests get a ✓, failing get an ✗, changed variables get a border and a tint.
  • The solve screen is fully keyboard-driven: ⌘↵ submits, ⌘⇧↵ runs, ← → step the trace, T toggles it, N takes the next problem.
  • Live regions announce run results and step narration, so a screen-reader user hears "line 4 set need = 4000" rather than nothing.
  • Panels are resizable but never below their minimum, and the drag handles are also arrow-key adjustable when focused.
